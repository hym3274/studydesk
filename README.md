# Desk

オセロを追加しました。`#/tools/02` がタイトル、`#/tools/02/match` が2人対戦です。
将棋と同じNeutralのUI・ぼかし背景・未終了対局の再開メニューを使い、タイトルだけ同梱Dela Gothic Oneを使用します。
提供された緑の盤画像を `src/assets/table.png` に同梱。石はCSSで描画します。

オセロのルールは独立したTypeScriptエンジンで実装しています。黒先手、8方向の反転、自動パス、両者が置けない場合の終局、引き分けに対応します。
待ったは自動パスも含めた着手前へ戻ります。合法手の点は手番の石と同じ色です。石数は対局中には表示せず、終局時だけ盤上の実数を表示します。大会の空きマス加算などは行いません。
参照: [World Othello Federation 公式ルール](https://worldothello.org/about/about-othello/othello-rules/official-rules/english)

保存キーは `desk.discs.v1` で、将棋と独立しています。初期配置から着手を検証して復元します。
文字入力中を除くZキーによるGoogle検索への移動にも対応し、対局保存に失敗したときは移動しません。
未対応: CPU・オンライン対戦・対局時計・棋譜の入出力。通常版と単体HTML版に含まれます。
Dela Gothic Oneのライセンスは `public/fonts/OFL-DelaGothicOne.txt` と単体HTML内に同梱しています。

Zキーで、同じタブのGoogle「英検準2級」検索へ移動します。対局中は移動前に保存し、保存失敗時は移動を中止します。
文字入力・IME変換中、修飾キー併用、キー長押しでは実行しません。検索には通信が必要です。
ブラウザの「戻る」でアプリへ戻れます。開いていたダイアログや駒の選択は復元せず、保存した対局を読み込みます。

単体HTMLのダウンロード版については [ダウンロード版の説明](docs/DOWNLOAD.md) を参照してください。

将棋を選ぶと「対人対戦」「詰将棋」「戦法解説」のメニューを開きます。従来の対局は `#/tools/01/match` に移り、保存キーは変えていません。
詰将棋はオリジナルの1手詰3問です。残り駒はすべて玉方の持ち駒として判定し、解の一意性・駒余りなしをテストしています。長手数問題・進捗保存は未対応です。
戦法解説は入口のみ（準備中）で、解説内容は未作成です。
メニューの筆文字タイトルには [Yuji Mai](https://github.com/Kinutafontfactory/Yuji) の「将棋」2文字を抽出したWOFFを同梱しています。ライセンスは `public/fonts/OFL-YujiMai.txt` にあります。
詰将棋のルールの参照先: https://www.shogi.or.jp/tsume_shogi/

React / TypeScript / Vite で作る、GitHub Pages 対応のゲームポータル。現在遊べるゲームは **同じ端末での将棋2人対戦**です。バックエンド、外部将棋ライブラリ、実行時の外部API・CDN・外部配信フォントを使用しません。

## 起動

Node.js **22.12以降の22系** と npm を使用してください。

```sh
npm ci
npm run dev
```

表示されたローカルURLを開いて「将棋」を選びます。対局への直接URLは `http://127.0.0.1:5173/#/tools/01` です。

## 操作

- 自分の駒をタップ（クリック）し、印のある移動先を選択します。選択した駒をもう一度タップすると解除します。
- 持ち駒は木の駒台から選び、盤上の合法なマスをタップして打ちます。同種の駒は重ねた表示と枚数で示します。空の駒台そのものには文字を表示しません。駒台の外側には、黒い駒形と「先手」・白抜きの駒形と「後手」を縦に表示します。
- 敵陣に関わる移動では成り・不成を選択します。強制成りは自動で処理します。
- 手番・王手・直前の手は盤の上に表示します。直前の手を押すと棋譜を開きます。
- 左上のメニューに、待った・盤面反転・対面モード・投了・持将棋・最初から・棋譜・ルール・一覧への移動をまとめています。
- 対面モードは初期状態でON。向かい側の駒台の持ち駒と先後の表示、手番、メニュー、成り・投了等の操作ダイアログを180度回転します。OFFでは操作表示を一方向から読みます。盤上の駒は通常の将棋と同じく、互いに向かい合う向きです。
- 矢印キーで盤上を移動、Enter / Spaceで選択、Escapeで選択を解除。ダイアログはEscapeで閉じられます。
- 投了とリセットは確認画面を挟みます。「待った」は一手戻します。投了・合意終局の直後はまず終局だけ取り消します。
- 千日手・持将棋の「もう一局」では盤面の向きも反転し、同じ場所に座ったまま先後を交代できます。

## 保存

着手、待った、終局、表示設定の変更ごとに `localStorage` の `minigames.shogi.v1` へ保存します。保存内容は指し手の配列と表示設定です。再訪時には初期配置から合法性を検証しながら指し直し、局面・持ち駒・棋譜・千日手の履歴・終局を復元します。盤面や王手フラグを保存ファイルの値のまま信用しません。

公開名・URLを変更しても保存キーは維持し、同じオリジンで既存の対局を引き続き読み取ります。公開ドメインやポート番号そのものを変えた場合、ブラウザのストレージは別になります。

ストレージ禁止・容量超過でもメモリ上で対局を継続できます。その場合は画面に通知し、閉じた後の復元は保証できません。壊れたデータや未知のバージョンは初期局面に戻し、通知します。別タブ間の対局同期は行いません。複数タブでは最後に保存した対局が残るため、対局は一つのタブで行ってください。

初回の画面・ゲームコード・画像・同梱フォントの読み込みには通信が必要です。読み込み後の対局操作は通信せず動作します。Service Workerによるオフライン再起動・インストール機能はありません。

## ルールと範囲

ルールエンジンはTypeScriptで独自に実装し、ReactとDOMに依存しません。

対応内容：全駒と成駒の移動、経路遮断、捕獲時の成り解除、成り・不成・強制成り、駒打ち、二歩、行き所のない駒、王手放置・自玉への王手の禁止、打ち歩詰め禁止、詰み、千日手、連続王手による千日手、投了。玉を取る手は生成しません。合法手が一手もない側は負けとします。

打ち歩詰めは歩が直接玉に王手をかけるときに、守備側の盤上の応手を全て検査します。隣接した歩の王手は駒打ちで遮断できないため、再帰的な駒打ち探索を必要としません。盤上の歩を進めて詰ます手は合法です。

千日手は盤面・双方の持ち駒・手番が同じ局面の4回目で判定します。最初から最後の同一局面までの区間において、一方の着手がすべて王手ならその側の負けです。王手を解除した局面で4回目が成立する場合も対象です。

持将棋は双方の玉が敵陣に入り、いずれの玉も王手でない局面で、双方の明示的な合意を求める24点制を用意しています。盤上・持ち駒の飛角を5点、それ以外（玉を除く）を1点で数えます。双方24点以上なら指し直し、24点未満の側は負けです。「詰ます見込みがない」ことは自動判定せず対局者が判断します。500手では、王手が続いていれば途切れたときに無勝負・指し直しとなります。

未対応：入玉宣言法（31点/24点の宣言・大会独自の27点制）、振り駒、時間制限・秒読み、駒落ち、棋譜ファイルの入出力、ドラッグ、CPU、オンライン対戦。待ったは練習用の機能で、公式対局の競技規則とは異なります。違法着手は事前に操作できないため反則負けにしませんが、連続王手の千日手は成立時に反則負けとします。

参照：[日本将棋連盟 対局規則](https://www.shogi.or.jp/match/taikyoku_rules/)、[2025年10月の修正](https://www.shogi.or.jp/match/taikyoku_rules/taikyoku_rules_revision.pdf)。持将棋等の大会固有の細則全てに対応する審判ソフトではありません。

## 検証

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`npm run test:watch` は開発用の監視モードです。専用のlint依存は追加せず、TypeScriptのstrict、未使用変数・引数、配列の未検査アクセスの検査を有効にしています。

自動テストは全駒・成駒の双方の方向、初期配置と初期合法手30手/2手深さ900局面、経路、捕獲、成り、禁手、王手・両王手、詰み、打ち歩詰めと逃げ道、千日手と連続王手、履歴復元、持将棋、保存・破損データ・ストレージ例外、120手の駒数保存を検証します。

今回の実行結果とブラウザ確認の詳細は [検証記録](docs/VERIFICATION.md) を参照してください。

ブラウザ確認では、ポータルからの起動、捕獲・成り/不成、持ち駒、待った、表示設定、投了・リセット、保存復元、狭い画面・横向き・Chromebook相当の画面幅、サブパスでの直接起動を対象にします。実機の学校Chromebook・スマートフォンでの性能・タッチ確認は別途必要です。

## GitHub Pages

1. このフォルダーをGitHubのリポジトリへpushします。ワークフローは `main` と `master` に対応します。
2. GitHubの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
3. `.github/workflows/pages.yml` が `npm ci` → `npm test` → 型検査とビルド → `dist` のアップロード → Pagesへのデプロイを実行します。PRでは検証のみ行います。
4. 公開URLは `https://<owner>.github.io/<repository>/`、将棋への直接URLは `https://<owner>.github.io/<repository>/#/tools/01` です。

Viteの `base` は `./` で、画像・CSS・遅延ロードするJSをリポジトリ名に依存しない相対パスにします。HashRouterを使用するので `#/tools/01` を直接開いたり再読み込みしてもサーバー側のリライトは不要です。`/tools/01` のようにハッシュを除いたURLは対象外です。旧URLのブックマークは新しいURLへ更新してください。

絶対サブパスが必要ならビルド時の環境変数 `VITE_BASE_PATH=/repository/` で上書きできます。

```powershell
$env:VITE_BASE_PATH='/repository/'
npm run build
```

カスタムドメインでは既定の相対パスのまま利用できます。公開先リポジトリやリモートはまだ設定していないため、この作業でGitHubへのpushや公開は実行しません。

### 公開される名前

ブラウザのタイトル・ロゴは `Desk`、ページのmeta descriptionは中立的なツールの説明、ルートは `#/tools/01` としています。`src/config.ts` でアプリ名とルートの生成を管理します。JavaScript・CSS・画像・フォントの配信名は `assets/<16進ハッシュ>.<拡張子>` にし、元のコンポーネント名や画像名を含めません。ソースマップは生成しません。

`npm run build` の最後に `npm run check:public` を実行し、HTMLのタイトル・説明文・公開ファイル名へ対象の旧名称等が入っていないことを検査します。画面内の「将棋」「ゲーム一覧」等、コード内のクラス名・保存キー、ソースリポジトリ内の名前はこの変更の対象外です。静的な画面・コードを非公開化する機能ではなく、外部の分類結果を保証するものでもありません。GitHubのユーザー名・リポジトリ名・ドメインはアプリの設定とは別にURLへ含まれます。

## 構成とゲーム追加

```text
src/
  portal/registry.ts        ゲーム登録情報（名前・画像・遅延ロードする画面）
  portal/App.tsx           ポータルとHashRouter用ルート
  components/Modal.tsx     ネイティブdialogの共通部品
  games/shogi/
    engine/types.ts        局面・指し手・履歴・終局の型
    engine/rules.ts        利き・王手・合法手・駒打ち判定
    engine/game.ts         初期配置・着手・終局・履歴・待った
    persistence.ts         保存・検証付き復元・ストレージ例外処理
    components/           盤面・駒・駒台の描画
    ShogiGame.tsx          対局UIとダイアログの操作状態
```

新しいゲームは `src/games/<name>/` に画面を作り、`portal/registry.ts` に1件追加します。公開用の `id` は `01`・`02` のような識別子にすると、URLへ名前を含めずに登録できます。一覧とルートが自動で増えます。未完成のゲームは登録しません。

CPU等は `getLegalMoves(position)` で候補を取得し、`playMove(position, move)` で入力を変更せず次の局面を作れます。対局として進める場合は `makeMove(game, move)` が履歴と終局を更新します。評価器は追加していません。UIが局面を直接変更する経路は設けていません。

## デザイン・素材

背景・メニュー・ダイアログは純白、主要な操作色は黒。文字は黒・濃い灰・中間の灰の3段階に揃え、灰色は区切り線や補助文字、ホバーなどに使用します。手数・直前の手の表示には囲み線を付けません。盤と駒台だけに木の素材を使用し、控えめな影で背景から区別します。常時表示は盤・駒台・先後の識別・手番・直前の手・左上のメニューボタンに絞り、コピーや操作パネルは置きません。UI・ロゴはNoto Sans JP、駒と盤の座標は明朝系を使用します。

Noto Sans JPは、現在の画面の文字とASCII・仮名・全半角文字を含む可変WOFFとして `src/assets/fonts/noto-sans-jp-ui.woff` に同梱しています。Google Fonts等への実行時のアクセスはなく、通常のビルドにフォント生成ツールは不要です。ライセンスは `public/fonts/OFL-NotoSansJP.txt` に同梱し、公開成果物にもコピーします。詳細と、画面の文言を追加したときの再生成手順は [フォント素材の説明](src/assets/fonts/README.md) を参照してください。

盤画像 `board.png` と木素材 `wood.jpg` は依頼者提供の画像を同梱しています。再配布・公開時の素材利用条件は依頼者の提供元に従ってください。駒はCSS、アイコンはローカルSVGです。提案時の生成画像は実行時の素材には使用しません。

将棋のサムネイルは、対局画面と同じ盤画像・共通の盤スタイル・`Piece` コンポーネントを使う表示専用の描画です。先手陣の左下4×4（9～6筋・六～九段）を切り出し、8八玉・7八金・6七金・7七銀を中心とした金矢倉を配置します。サムネイル独自の駒の形や色は用意せず、実際の対局と木目・書体を共有します。ボタンや対局データへの読み書きはありません。

登録情報の `thumbnail` は画像URLと表示コンポーネントの両方に対応し、代替テキストは `thumbnailAlt` で管理します。
